01 / Limits

The current path is powerful—but narrow.

Today the product is optimized around one ideal setup. Expansion starts by removing the assumptions that prevent it from travelling.

01

Local only

Chrome, localhost HTTP, visible elements, and a machine where lsof can find the server.

02

One destination

Every review is coupled to a live herdr pane instead of a portable delivery contract.

03

One-way handoff

The browser sends a note, but never sees acknowledgement, progress, questions, or completion.

04

Ephemeral context

No drafts, history, shared review state, full flows, or durable record beyond files in /tmp.

02 / Direction

Give the product a larger job.

Do not build another issue tracker or another DevTools clone. Own the handoff between what a person sees and what a developer or agent needs to change it.

Recommended product statement
Select anything in a running application, capture enough technical context to locate and reproduce it, and send it to any coding agent or issue tracker.
03 / Foundations

Five changes unlock most of the expansion.

These are platform capabilities rather than isolated features. Each one makes several future use cases possible.

FOUNDATION / 01

Explicit project integration

Make process inspection a fallback. A Vite, Next, or framework plugin should identify the project and expose reliable source metadata.

  • Works in Docker, WSL, forwarded ports, and monorepos
  • Supports React 19 without private fiber fields
  • Exposes component name, source file, props, and route
FOUNDATION / 02

Destination adapters

Keep herdr, but stop making it the only endpoint. Reviews should move through a stable adapter interface.

  • MCP and local CLI
  • GitHub, Linear, Jira, Slack, and webhooks
  • Markdown and structured JSON export
FOUNDATION / 03

Durable review sessions

Persist drafts, annotations, status, and history. A reload should never destroy an unfinished review.

  • Edit, delete, reorder, and reselect annotations
  • Group multiple routes into one review
  • Resolve, reopen, export, and share
FOUNDATION / 04

Closed feedback loop

Bring agent state back into the page: queued, working, blocked, complete, and ready for verification.

  • Show questions and changed files
  • Reload and highlight the affected element
  • Accept the result or send a follow-up
FOUNDATION / 05

Versioned context collection

Collect useful context through independent capabilities, with clear permission and payload boundaries.

interface ContextCollector {
  id: string;
  supports(page: PageContext): boolean;
  collect(selection: Selection): Promise<ContextResult>;
}

04 / Capabilities

Expand what can be reviewed.

Element comments remain the fastest path, but they become one tool inside a richer review session.

⌖

More annotation types

  • Point, region, element, and page-level notes
  • Recorded interaction flows
  • Expected-versus-actual comparisons
  • Priority, category, and status
◫

Richer visual context

  • Cropped and full-viewport screenshots
  • Before-and-after captures
  • DOM fragment and component ancestry
  • Viewport, route, browser, and operating system
≋

Runtime diagnostics

  • Console errors and warnings
  • Failed and slow network requests
  • Accessibility violations
  • Application reproduction state
✣

Framework coverage

  • React 19 and Next.js
  • Vue, Svelte, Astro, and Solid
  • Storybook component resolution
  • Build-time source markers stripped in production
↔

Serious live editing

  • Box model, flex, grid, and typography controls
  • CSS variables and design tokens
  • Undo, redo, responsive edits, and generated CSS
  • Multi-element changes
◎

Automated review

  • Accessibility and responsive scans
  • Overflow, clipping, and broken-image detection
  • Token and spacing inconsistencies
  • Visual regression against a baseline
05 / Architecture

Separate the four things that currently move together.

Stable extension points keep project discovery, evidence gathering, persistence, and delivery independently replaceable.

01 / ProjectResolver

Where is this?

Maps a page and environment to a repository, source root, framework, and project identity.

02 / ContextCollector

What happened?

Collects selected visual and technical evidence without forcing every review to carry everything.

03 / ReviewStore

What is its state?

Owns drafts, durable IDs, history, comments, status changes, and retention.

04 / Destination

Who should act?

Delivers a normalized review to herdr, another agent, an issue tracker, or a webhook.

PROJECT METADATA / EXAMPLE

Prefer explicit identity over process inference.

A tiny development plugin makes project and source resolution deterministic while keeping lsof as a zero-config fallback.

designMode({

06 / Roadmap

Build outward in four controlled moves.

Reliability comes first, reach second, context third, and the collaborative loop last.

01

Dependable every day

  • Persist drafts and sessions
  • Edit and remove annotations
  • Fix exact style restoration
  • Add extension and browser tests
  • Add local pairing and restrictive CORS
  • Version the wire protocol
Foundation
02

Reach more projects

  • Vite and Next integration
  • Explicit project registration
  • React 19, Vue, and Svelte
  • HTTPS and custom local domains
  • Remote ports and containers
  • Webhook and Markdown adapters
Distribution
03

Comprehensive reviews

  • Viewport and full-page captures
  • Console and network collectors
  • Accessibility evidence
  • Point, region, page, and flow notes
  • Multi-route sessions
  • Priority and review status
Capability
04

Close the loop

  • Agent progress in the browser
  • Follow-up questions
  • Changed-file reporting
  • Before-and-after verification
  • Accept and reopen workflow
  • Shareable team reviews

07 / Priorities

If only five things ship, ship these.

This sequence expands the addressable use case without losing the product’s speed and focus.

Rank Improvement Why now Impact
01 Explicit project and source integration Removes the largest compatibility constraint and makes source locations dependable. Very high
02 Destination adapter interface Makes the product useful beyond herdr without rebuilding the browser experience. Very high
03 Persistent, editable sessions Turns a fragile one-shot action into a workflow people can trust for real reviews. High
04 Richer opt-in context collectors Gives developers and agents enough evidence to reproduce difficult issues. High
05 Agent status and verification loop Creates the differentiated end-to-end experience rather than another handoff tool. Strategic

The differentiator is not annotation. It is actionable context.

Keep selection instant, make project resolution dependable, collect only the evidence each review needs, and let the result return to the same place where the problem was found.
